  defense.

⏺ Payment::BulkSettlement is written and bin/ci passes (14 tests). Nothing is
  committed.

  Files
  - app/models/payment/bulk_settlement.rb
  - test/models/payment/bulk_settlement_test.rb

  Behavior
  - Payment::BulkSettlement.new(payer_id:, entries:).settle takes entries that
    respond to payee_firm_id, amount_cents and description. BulkPayment::Item
    fits.
  - One transaction does the following:
    - It locks all involved firms in one query, Firm.where(id: 
      ids).order(:id).lock.
    - If the payer's balance is short, it raises InsufficientFunds and rolls
      back.
    - It debits the payer, credits each payee once, summing duplicate payees,
      and creates the Payment rows. It returns those payments.
  - On ActiveRecord::Deadlocked it retries the whole transaction, up to
    MAX_ATTEMPTS = 3, then re-raises.

  Tests cover
  - The happy path with duplicate payees.
  - Spending the whole balance.
  - Insufficient funds leaving everything unchanged.
  - The payer listed as a payee, which nets to zero.
  - A retry that succeeds, and a retry that gives up after 3 attempts.

  Caveats
  - Minitest 6 has no stub, so the deadlock tests temporarily override
    Firm.where by hand.
  - I haven't added a real multi-thread test, such as opposite-direction A↔B
    transfers or concurrent overdraw attempts. Those need non-transactional
    tests with cleanup. The deadlock prevention rests on the order(:id).lock
    query, and I haven't shown it works under concurrency. Want me to add that
    test?
  - The retry only helps at top level. If settle is called inside an outer
    transaction, a deadlock aborts that outer transaction and can't be retried
    here.
  - A payee id missing from the DB raises KeyError. BulkPayment validation

  Flow: POST /bulk_payments
  1. BulkPaymentsController#create permits the params.
  2. BulkPaymentRequest validates them, resolves uuids to ids with one read-only
     query, and converts amounts to cents.
  3. Payment::BulkSettlement does the work in one transaction: lock, funds
     check, debit, credit, insert. It retries on deadlock.
  4. Responses: 201 with no body, or 422 with errors.
